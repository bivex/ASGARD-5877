## [0.3.0] - 2026-10-27

### Added
- Implemented coverage-guided structure-aware Stack-VM fuzzer (`tools/vm_fuzz_harness/`): libFuzzer+ASan+UBSan harness whose input is *plaintext* bytecode encrypted under the real key schedule (SipHash-1-2 entry key + fmix64 rolling stream) so `stack_vm_run` dispatches valid handler sequences — reaching semantic handler edge cases (div-by-zero, stack underflow, slot OOB, shift counts > 63) that ciphertext tampering can never hit; plus a dependency-free standalone stress mode (verified 200k runs @ 1.2M exec/s, 0 invariant violations).
- Add the deobfuscation probe harness (`examples/deobf_probe/`): `peephole_eval.py` runs a seed-blind one-pattern attack (universal stack identities + O(log n) dead-slot junk rules) over the per-phase JSON dumps and reports how much of each pass's output is pattern-reversible; `dispatch_topology.py` measures bytecode CFG hub concentration and detects machine-code epilogue re-centralization in the compiled runtime; `run_probe.sh` drives both over a doubly-protected `examples/license_check.c`. First findings recorded in the README: avid/multiplicity output is fully pattern-reversible (26.3% of the 1.08M-op final program; 0.0% with those passes off), the CFF bytecode CFG is dispersed (max in-degree 5.1%), and clang merges the per-handler dispatch epilogues into one shared `br` trampoline (257 predecessors), so the "0 CFG hubs" claim of the pipelined-dispatch spec does not survive codegen.

  * Added flag state evaluation (`PushFlags; PopFlags`) forcing emulators to materialize lazy condition codes on each iteration.
  * Calibrated default iteration count to $N = 500$ ($0.05-0.18\text{ s}$ native baseline, preserving interactive UX while exposing emulators to $2^{500}$ symbolic path divergence).
- Expose computational stalling parameters through CLI and configuration system (`bin/cli_protect_arm64.ml`, `bin/cli_protect.ml`, `bin/cli_protect_riscv.ml`, `lib/adapters/protect_adapters/config_adapter.ml`): added `--comp-stall`, `--comp-stall-iterations`/`--stall-iters`, `--comp-stall-variant`/`--stall-variant`, and `--comp-stall-seed` CLI arguments; eliminated hardcoded iteration counts and magic numbers across `lib/adapters/protect_adapters/vm_packagers.ml` and `lib/stack_vm/stack_stall_pass.ml`.

### Fixed

- Fix zero register check in native VM atomic emitter: the zero register shares its slot index with the GS base register in the native register file, so checking `is_zero_register dst` instead of slot index equality ensures `vzero` writes are ignored without suppressing writes to `vgs_base` (`lib/native_vm/vm_emitter.ml`).
- Fix canonicalization of `Ir.Ccmn` and `Ir.Ccmp` with immediate operands outside the 5-bit `0..31` range or memory operands (`lib/native_vm/vm_transform.ml`): ARM64 `OP_CCMN_RI` and `OP_CCMP_RI` words allocate only 5 bits for the immediate operand, so `cmn`/`ccmn` and `ccmp` with larger immediates (e.g. `cmn w0, #100`) wrapped modulo 32 when emitted directly; `canonicalize_instr` now loads out-of-range immediates and memory operands into a scratch register and lowers to `OP_CCMN_RR`/`OP_CCMP_RR`, resolving test 8 in `Native VM Sub-width Semantics` (`e2e_sub64_signed_comparisons_clang_o2_o3`).
- Restore the metamorphic variants of the atomic handlers `H_ATOMIC_ADD` and `H_ATOMIC_SWP` in the native VM runtime. The width-aware rewrite of the LSE atomics left both handlers with a single fixed body, so every seed produced the same code and the metamorphism invariant (`H_ATOMIC_ADD diversity > 1`) failed. Both handlers now emit three semantically equivalent variants - the `__atomic` builtin, the C++ atomic member and a load/compare-exchange loop - and all three honour the width code in the word's extra bits (32-bit, 16-bit, 8-bit and 64-bit).
