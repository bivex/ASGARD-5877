# ASGARD-5877 nn_metamorph — нейросетевая эмуляция метаморфных ядер

MLX-нейросети (Apple Silicon) учатся вычислять то, что вычисляют
метаморфно-защищённые ядра ASGARD: `asgard_fuzz_compute` (ULTRA) и
`asgard_fuzz_mix` (VIRTUALIZE) из `examples/diff_fuzz`. Скрипт-лестница
архитектур (`--sweep`) показывает, какая ёмкость NN что способна выучить —
и через это видно, где метаморфизм прячет семантику, а где нет.

```
              TestPayload (40B) / (seed, blob)            метаморфный вывод u64
                        │                                          ▲
        ┌───────────────┴───────────────┐            ┌─────────────┴─────────────┐
        │ numpy bit-точный референс     │            │ vm_out/protected_proj    │
        │ (kernel_ref.py, 14M вект/с)   ╞══ валидация═══ (реальный ASGARD VM)  │
        └───────────────┬───────────────┘    30k     └───────────────────────────┘
                        │ бит-фичи (296/646) + байт-токены (37/73)
        ┌───────────────┴────────────────────────────────┐
        │ MLX: MLP (256×2 … 1024×6)                      │
        │     BitTokenTransformer (d128/L2 … d256/L4)    │──► 64 битовых логитов
        └─────────────────────────────────────────────────┘     BCE per bit
```

## Быстрый старт

```bash
./examples/nn_metamorph/run.sh                     # валидация + полная лестница (~7 мин)
python3 examples/nn_metamorph/train.py --sweep --rung 'mlp-s|xf-s'   # подмножество
python3 examples/nn_metamorph/train.py --arch mlp --width 512 --depth 4 --epochs 12
```

Требования: `mlx >= 0.31`, `numpy` + бинарники `examples/diff_fuzz/vm_out/`
(строит `run_diff_project.py`). Все записи прогонов падают в
`results/results.jsonl` — сравнение архитектур накапливается между сессиями.

## Ground truth

`kernel_ref.py` — векторизованная бит-точная numpy-реализация обоих ядер
(маскированный 19-шаговый цикл, saturating-каст ARM `fcvtzs`, RNE
double→float, uint64-wraparound). `validate_ref.py` прогоняет 30 000
boundary-взвешенных векторов (то же распределение, что у дифф-фаззера)
через **реальный защищённый бинарник** и нативный golden и требует
побитового совпадения. Так как дифф-фаззинг гарантирует parity 100%,
референс = выход метаморфного VM.

## Метрики

| Метрика | Смысл |
|---|---|
| `bit_acc` | точность по 64 выходным битам (0.5 = монетка) |
| `lo32/hi32` | точность младшей/старшей половины слова |
| `hamming` | среднее расстояние Хэмминга до истины (32 = случайно) |
| `exact` | доля точных 64-битных совпадений |
| `p_early/p_full` | точность на early-exit пути против полного пути (compute) |

## Честные ожидания (это результат эксперимента, а не провал)

* **Выучимо**: early-exit путь compute `(a^0x5877)+b mod 2^64` — бит j суммы
  зависит только от входных битов ≤ j (carry chain): `p_early` заметно выше
  0.5. Неожиданный эмпирический сигнал первой кампании: старшая половина
  слова выучивается лучше младшей (hi32 ≈ 0.71 vs lo32 ≈ 0.58 у mlp-s) —
  грубая high-bit структура суммы даётся градиентному спуску легче, чем
  точные младшие XOR+carry биты. FP-ветвления (`q2 > 1e12`, `q2 == 0`,
  насыщение каста) — локальные битовые предикаты по знаку/экспоненте, MLP
  их берёт.
* **Не выучимо**: полный путь compute (splitmix-лавина + mul/xorshift +
  цикл) и весь `mix` (FNV-подобный хеш) — выходной бит зависит от почти
  всех входных битов через нелинейную обратную связь: `p_full ≈ 0.50`,
  hamming ≈ 32 у любой архитектуры. Именно это и есть эффект метаморфной
  лавины с точки зрения black-box атакующего.
* Трансформер на фиксированных битовых полях не обгоняет MLP per-FLOP —
  лестница это показывает явно; возможное исключение — `mix`
  (последовательность байт), который всё равно наименее выучим.

## Лестница архитектур

Редактируемый список `LADDER` в начале `train.py` — им и итерируют:

| rung | архитектура | epochs | lr | batch |
|---|---|---|---|---|
| mlp-s | MLP 256×2 | 12 | 1e-3 | 4096 |
| mlp-m | MLP 512×4 | 12 | 1e-3 | 4096 |
| mlp-l | MLP 1024×6 | 8 | 1e-3 | 4096 |
| xf-s | Transformer d128 L2 h4 | 8 | 3e-4 | 1024 |
| xf-m | Transformer d192 L3 h6 | 6 | 3e-4 | 1024 |
| xf-l | Transformer d256 L4 h8 | 4 | 3e-4 | 512 |

Эпохи больших трансформеров урезаны (~56 с/эпоха при 200k сэмплов).
`--loss mse` — абляция лосса; по умолчанию BCE per bit.

## Первая кампания (M-series Mac mini, 200k train / 20k val)

| rung | params | время | bit_acc | exact | p_early | p_full |
|---|---|---|---|---|---|---|
| **mlp-s** | 158k | **1.6с** | **0.6477** | **12.0%** | **0.831** | 0.505 |
| mlp-m | 972k | 7.4с | 0.5897 | 4.1% | 0.698 | 0.505 |
| mlp-l | 5.6M | 23.5с | 0.5730 | 0.9% | 0.661 | 0.504 |
| xf-s | 319k | 120с | 0.6444 | 12.1% | 0.824 | 0.504 |
| xf-m | 972k | 202с | 0.6450 | 11.3% | 0.824 | 0.506 |
| mix: mlp | — | <1с | 0.4994 | 0% | — | — |

Выводы для итерации: mlp-s — pareto-победитель (xf-m в 75× дороже при той же
точности); избыточная ёмкость при фиксированных lr/эпохах вредит; хеш-пути
неучимы (монетка). Следующий шаг — lr-schedule/эпохи для mlp-m/l.

## Раскладка

```
kernel_ref.py     бит-точный numpy-референс ядер (ground truth)
validate_ref.py   сверка референса с реальными бинарниками (--fuzz протокол)
dataset.py        сэмплирование, бит-фичи, токены (LSB-first конвенция)
models.py         MLP + BitTokenTransformer (mlx.nn)
train.py          CLI, обучение, метрики, LADDER sweep, results.jsonl
run.sh            полный прогон: валидация → compute sweep → mix sweep
results/          results.jsonl — накапливаемые записи прогонов
```

## Связь с развитием ASGARD

Выучиваемость I/O — прокси стойкости защиты против black-box моделирования:
чем меньше сигнал достаётся сети данной ёмкости, тем меньше пользы атакующему
от «запоминания» поведения защищённой функции. Расширения: сравнить
выучиваемость ядер с разными наборами трансформаций (CFF/MBA on/off),
добавить ядра из `examples/cpp_types_demo`, обучать на выходе разных seed
сборок (метаморфные варианты) и мерить перенос.
